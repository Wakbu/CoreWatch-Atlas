# CoreWatch-Atlas Web 대시보드 설계 기준

이 문서는 사용자가 제시한 화면 스케치를 이후 Web MVP에서 그대로 이어가기 위한 UI 기준이다. 이번 Server/API 1단계에서는 UI 코드를 구현하지 않는다.

## 기본 레이아웃

- 기존 CoreWatch 개인 사용자판의 정보 밀도, 색상 감각과 사용 흐름을 참고하되 WPF 화면을 복제하지 않는다.
- 왼쪽에는 접고 펼칠 수 있는 기능 목록을 둔다.
- 오른쪽 콘텐츠 영역은 데스크톱·태블릿·모바일에 맞춰 반응형으로 재배치한다.
- 첫 페이지는 등록된 전체 서버를 빠르게 훑는 통합 대시보드다.

## 첫 페이지

등록 서버마다 상태 카드를 하나씩 표시하고 서버가 늘어나면 반응형 그리드에 모두 배치한다.

카드의 기본 정보:

- 서버명, 운영체제와 온라인·오프라인 상태
- CPU·메모리·디스크의 현재 사용률
- 마지막 수집 시각과 활성 경고 수

카드를 선택하면 해당 서버 상세 페이지로 이동한다. 상세 페이지에는 CPU·메모리·디스크·네트워크 차트, 시스템 정보, 경고와 기간별 이력을 둔다.

서버 카드 아래 공간은 다음 순서로 사용한다.

1. 전체 서버·온라인·오프라인·경고 요약
2. 즉시 확인이 필요한 경고 서버
3. 최근 경고와 상태 변경 이벤트
4. CPU·메모리·디스크 사용률 상위 서버

## 왼쪽 기능 목록

- 대시보드
- 서버
- 경고
- 이력
- Prometheus 연동
- 설정

펼친 상태에서는 아이콘과 이름을, 접힌 상태에서는 아이콘과 도움말을 표시한다. 모바일에서는 오버레이 메뉴로 전환한다.

## 상태와 예외 화면

- 서버가 없으면 Agent 등록 안내와 시작 동작을 표시한다.
- 로딩, 일부 API 실패, 전체 오류, 검색 결과 없음 상태를 각각 구분한다.
- 색상만으로 상태를 전달하지 않고 아이콘·문구를 함께 사용한다.
- 카드 키보드 이동, 명확한 포커스와 충분한 대비를 제공한다.
